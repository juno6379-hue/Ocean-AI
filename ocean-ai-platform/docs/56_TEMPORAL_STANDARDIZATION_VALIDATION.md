- 범위: 원천 시계 기준 2000-01-01 00:00:00~2000-12-31 23:56:00. UTC로 간주하지 않는다.
- 파싱 57,580행, 오류 0행; 선택한 OTT/APR/ASP 3개 항목 172,740개 값.

결측은 현재 원천 파서가 인식하는 빈 값/NaN/@의 집계다. -999는 자료별 정의가 없는 상태에서 결측으로 확정하거나 정상 물리값으로 공개하지 않는다. 검토 후보는 `abs(value-median)>6×1.4826×MAD`의 탐색 결과이며 계절·태풍·센서 변경을 반영한 정밀 QC 결과가 아니다. MAD=0/자료 없음은 이상 없음이라는 판정을 하지 않는다. 원천 QC1/QC2는 항목별 원문 분포로 보존했다.

2000년 파일의 기대 수집주기가 확정되지 않아 최대 공백을 누락 건수로 환산하지 않았다. 2023/2024 이력집의 1분 주기를 소급 적용하지 않는다. 상세: [CSV 검증](<local-evidence-root>/2026-09-29/new-chat/outputs/validation-standardization/csv-prevalidation.json).

## 2. 시계열 표준화 식별·시간 계약

계층을 `관측소 → 항목 채널 → 물리 센서 → 설치/운용 구간 → 관측행`으로 나눈다.

| 개체 | 식별·필수 내용 | 금지할 추정 |
|---|---|---|
| 관측소 | 원천 namespace+원천 ID, 명칭·좌표 및 변경기간 | 접두사/밑줄 제거 후 통합 |
| 채널 | 관측소+원천 항목+TE_CODE | 채널 ID를 물리 센서 일련번호로 간주 |
| 장비 | 제조사·모델·장비번호/일련번호·원천 코드별 별칭 | 번호만 같으면 동일 장비로 합침 |
| 운용 이력 | 설치·교체·철거·교정, 적용 시작/종료, 증빙, 승인 버전 | 현재 상태를 과거로 소급 |
| 관측행 | 원천 값/단위/시각/QC, 표준 값/단위/UTC, 설치구간 ID, 출처 해시 | 원천 값을 덮어쓰거나 보고일로 시간 대체 |

유효기간은 `[시작, 종료)`다. v1은 시작·종료가 검토된 범위만 연결한다. 종료일 NULL이 '계속 운용'인지 '모름'인지 구분할 원천 계약이 없으면 무기한으로 해석하지 않는다. 월 단위 설치일은 월 정밀도로 보존하고 1일 00시로 만들지 않는다. `valid_time`과 근거 수집시점 `recorded_at`을 분리한다. 표준 시각은 UTC이며 KST 변환은 개별 원천의 시계가 확인된 뒤 적용한다.

조위 기준면은 단위 변환과 별도다. cm→m 변환만으로 기준면이 같아지지 않으며 수측기점 높이를 조위 값에 자동으로 더하거나 빼지 않는다. 기압은 관측고도·현지/해면기압, 풍속은 설치고도·평균시간·방향 기준도 확보해야 한다.

실행 모듈은 cm→m, hPa→Pa, m/s 유지의 좁은 변환만 지원한다. 전체 66개 항목의 변환기를 완성했다는 의미는 아니다. 원천 해시 불일치, 센서 적용 구간 공백·중첩, 미확정 센티널, 중복 표준 키는 배치 공개를 차단한다. [계약](<local-evidence-root>/2026-09-29/new-chat/outputs/validation-standardization/temporal-standardization-contract.json), [실제 차단 결과](<local-evidence-root>/2026-09-29/new-chat/outputs/validation-standardization/actual-standardization-gate.json).

## 3. QC 규칙과 실행 순서

1. 원천 무결성·구조·파싱을 검사하고 부적합 파일/행을 별도 판정한다.
2. 원천 키 중복·값 충돌·결측·시간 역전·공백·탐색 이상치를 검사한다.
3. 검토된 원천 역할, 관측소, 항목, 단위, 시간대, 센서 구간, 기준면, QC 보존 정책으로 표준화한다.
4. 표준행 필수키·UTC·값·중복·수량 정산을 검증한다.
5. 해당 관측소/센서/변수/유효기간에 승인된 정밀 QC만 실행한다.
6. 원천 QC, 자동검사 결과, 담당자 검토, 승인 학습 라벨을 분리한다.

정밀 QC 규칙에는 규칙 ID/버전, 표준 단위, 적용 기간, 근거, 임계값이 필요하다. 현재 모듈은 범위·변화율·고착 검사를 제공하며 센서 교체, 자료 공백, 미검사 구간을 넘어 값을 비교하지 않는다. 규칙/단위/기간이 없으면 NOT_EVALUATED다. 범위 검사의 PASS를 전체 QC 통과로 집계하지 않는다.

사용자 지정 품질관리 가이드의 WT/LO/ER/GR/GD/RL/SP/RR/SR/ST/DE/PO는 기준 알고리즘 분류로 연결했다. 본 구현이 가이드의 모든 알고리즘·임계값을 그대로 구현한 것은 아니다. 계절/지역/조석 잔차/항목 간 일관성, 지연시간·전원 검사는 입력과 승인 규칙을 보강해야 한다. 수신시각이 없으면 지연 검사를 실행하지 않는다. ## 4. 문서 데이터 표준화

문서 원본 ID는 전체 SHA-256, 문서 버전은 원본 해시·추출 버전으로 관리한다. 구조 분류와 업무 분류를 분리하고 혼합 문서는 시트·절·표 행마다 업무 태그를 부여한다. 업무 범주는 관측/예측분석/QC기준/QC결과/점검/유지보수/센서이력/기준정보/운영보고/매뉴얼/소스/미확정이다.

필수 메타데이터는 원본 경로·해시, 업무 분류, 보고일, 사건 시작/종료·정밀도, 관측소 후보, 장비 표현, 항목, 페이지·시트·행 위치, 매핑 상태, 파서·근거 버전이다. 보고 기준연도를 사건일이나 정확한 발행일로 대체하지 않는다. PDF 페이지와 인쇄면 번호는 별개다. XLSX/HWP 등에 PDF 페이지 번호를 만들어 넣지 않는다. 추출 시 NUL 등을 정리하더라도 원본 해시와 위치를 보존한다.

이력집 2개는 본문 확인 근거와 위치를 연결했고, 전체 71,957개 파일에는 경로·헤더 기반 업무 태그 후보만 부여했다. **전체 문서 내용 확정이나 임베딩 재실행은 하지 않았다.** [문서 대장](<local-evidence-root>/2026-09-29/new-chat/outputs/validation-standardization/document-standard-register.json), [업무 태그 후보](<local-evidence-root>/2026-09-29/new-chat/outputs/validation-standardization/business-classification-candidates.jsonl).
