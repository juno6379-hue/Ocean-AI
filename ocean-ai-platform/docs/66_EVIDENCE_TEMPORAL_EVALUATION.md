## 실제 RDB

접속 대상은 기존 localhost:5432/ocean_ai_db, 새 스키마는 evidence_eval이다.
기존 public/foundation 관측값·승인 상태는 변경하지 않았다.

| 테이블 | 역할 |
|---|---|
| evidence_eval.run | 입력/출력 해시·foundation 실행·완료 시각 |
| assertion | 문서 ID/쪽/발췌 또는 원천 관측소 메타데이터의 미검토 주장 |
| period_candidate | 운영/항목/센서 기간 후보. 현재 항목 운영 구간 적재는 0 |
| coverage_review | 관측 범위마다 평가 준비를 막는 이유 |
| temporal_candidate | 같은 원천 관측소 문자열의 구간 교차 및 항목 호환성 후보; 현재 0 |
| dataset_snapshot | 고정 입력에 대한 업무별 준비 상태 및 내용 hash |
| benchmark_protocol | 업무별 비교 방법과 protocol hash |

v_dataset_readiness는 최근 실행의 업무별 준비 상태를 보여주고,
v_temporal_review는 문서 기간 후보와 관측 범위의 연결 후보를 보여준다.
이 스키마는 검토 후보 snapshot이라 APPROVED로 바꾸거나 사용 member를 추가할 수 없다.
실제 승인 원장과 행 단위 membership 생성/조회 화면 연결은 후속 작업이다.

적재는 출력/SQL hash, 단일 transaction, advisory lock, 대상 DB 확인,
외래키·행 수 정산을 적용했다. DB에서 후보를 APPROVED로 변경하거나 BLOCKED 데이터셋에
member를 추가하는 쓰기가 거부됨을 SAVEPOINT 롤백 검사로 확인했다.

## 이번에 발견한 연결 문제

2013-01-01 DT 파일럿의 원천 관측소 코드는 **78**이다. 인천 문서의 DT_0001과 다르다.
이 둘을 동일 관측소로 연결하려면 MDC 원천 코드 대응표/별칭 이력 근거가 필요하다.
해당 파일럿 항목은 dt_tide1/dt_apress/dt_wspeed여서 C/T 사용 이력으로 센서를 지정할 수 없다.
따라서 기간 후보가 2013년 1월을 포함해도 관측 연결을 승인하지 않는다.

자동 추출된 날짜 언급에는 보고서 기준월·수집률 표·다른 관측소의 이력 등이 섞일 수 있다.
이를 사건 또는 동일 관측소로 단정하지 않고 본문 위치·발췌와 함께 검토 목록으로 적재했다.
문서 제목 연도를 사건 연도로 대입하거나 한 페이지의 날짜/serial을 다른 행에 전파하지 않는다.
설치/측정 개시/교정/회수와 자료 보유 기간·수집 시각·DB 적재 시각을 별개로 보존한다.

## 데이터셋 확정 전에 남은 것

1. 문서 456개에서 자동 추출한 후보를 실제 사건·관측소·항목·serial로 검토/구조화한다.
   원문 표의 행/열 관계와 누락·문서 간 충돌을 확인해야 한다.
2. 관측소 코드 78/DT_0001 같은 원천 간 별칭을 검증하고, 관측소별 개소/이설/휴지/재개 구간을 확정한다.
3. 항목별 관측 개시/중단, 센서 배치·교정 구간, 단위·시간대·당시 QC 적용 기간을 승인 근거와 연결한다.
4. 전체 Parquet 원천 중 미연결 2,570개를 프로파일하고, 실제 행 membership·결측·중복·QC 유효 건수를 고정한다.
5. 예측은 시간순 분할과 정답 horizon 간격, 이상 탐지는 사건 단위 분할 및 정답,
   검색은 담당 검토 qrels, 보고서는 주장·인용 검토 정답을 준비한다.

이 단계의 미확정은 단순 담당 승인 한 번으로 없어지는 것이 아니다. 근거 추출·기간 구조화·
원천 코드 연결·행 단위 데이터셋 생성 코드도 더 구현해야 한다.

## 모델 비교 구현과 한계

코드 위치: backend/app/scripts/evidence_evaluation/.
temporal.py / build.py / schema.sql / benchmark.py / evaluate.py / test_evidence_evaluation.py.
실행 방법과 JSON 입력 계약은 해당 README.md를 참조한다.

| 업무 | 구현된 점수 계산 | 추가로 필요한 평가 |
|---|---|---|
| 예측 | MAE·RMSE·기준선 대비 skill | 관측소별 집계/미관측소 평가/불확실성, 실제 후보 실행 |
| 이상 탐지 | Precision·Recall·F1·오탐률 | 사건 단위 탐지율·탐지 지연·일당 오경보, 실제 정답 구축 |
| 검색 | Recall@k·MRR@k·nDCG@k | 답 없음 판단·개정판 누수 검증, 공정한 corpus/qrels |
| 보고서 | 담당 검토 기반 주장 근거율·인용 정확도·필수 사실 포함률 | 실제 생성, 블라인드 담당 검토·숫자/날짜 확인 |

evaluate.py는 고정한 동일 test_case_ids와 동일 정답을 사용해 후보 결과를 비교한다.
승인 데이터셋·분할 검증·model digest·hardware 기록이 없으면 거부한다.
허용 오차·최소 recall·최대 지연·예산은 업무별 requirements의 min/max로 설정한다.
현재 운영 임계값은 임의로 확정하지 않았다. 검증셋에서 정한 조건은 테스트 전에 고정해야 한다.

처리시간은 사례별 실측 latency의 p50/p95를 계산한다. 원격 모델은 실청구액/통화,
로컬 모델은 측정 전력과 단가를 기록할 수 있다. 비용 미측정은 NULL이며 0원으로 해석하지 않는다.
장비 감가·인건비·저장 비용을 포함한 전체 운영 원가 산정은 별도다.

외부 API 호출·새 모델 설치·실측 데이터 신규 학습·모델 최종 선정은 이번에 수행하지 않았다.
후보 결과 채점기의 입력 승인 표시는 신뢰 가능한 승인 원장에서 내보낸 자료를 전제로 한다.
임의 JSON 자체로 승인을 인증하는 운영 API를 구현한 것은 아니다.

## 드라이브 공간 및 이동 판단

이번 확인 시 C: 여유 35,575,463,936 B(약 33.1 GiB), D: 여유 1,990,433,329,152 B(약 1.81 TiB).
D: 루트 읽기는 가능했으나 Win32_LogicalDisk 상세 조회는 권한 거부되어 디스크 종류/물리 상태는 미확인이다.
대용량 원천/레이크의 D: 이전이 적절하지만 아직 파일 복사·삭제·경로 전환은 수행하지 않았다.

권장 최종 위치는 D:\AI_Observation 아래 project/source/data_lake/metadata/backup 역할을 구분하는 구조다.
구체적 디렉터리·백업 정책은 실제 의존성 점검 후 확정한다. 이전은 복사→해시·행 수 검증→경로 전환→
기능 검증→C: 원본 정리 순서다. 검증 중에는 이중 보관, 전환 완료 후에는 실행/원천 기준본을 하나로 관리한다.
기존 manifest 절대 경로는 원래 계보로 보존하고 실제 저장 위치 매핑을 추가해야 한다.
가상환경·Docker/PostgreSQL·Chroma 영속 데이터는 단순 이동으로 전환하지 않는다.
