## 2. 정형데이터 분류와 작업

### 2.1 운영 관측 원천

대상: `분류/정형데이터/01.정형데이터/2023`, `2024`, `2025`, `2026`의 `data_YYYYMM.csv` 115개.

필수 작업:

1. 파일별 인코딩, 구분자, 헤더, 컬럼 수, 행 수, 최소·최대 시각을 자동 검사한다.
2. 관측소 ID, 센서 ID, 관측항목 코드, 관측시각, 값, 원시 상태값을 표준 컬럼으로 매핑한다.
3. 모든 시각을 UTC 또는 KST 중 하나로 저장하고 원본 시간대와 변환 규칙을 메타데이터에 기록한다.
4. 숫자 변환 실패, 물리 범위 초과, 중복 키, 시간 역전, 결측을 별도 오류 테이블에 남긴다.
5. 원본 파일의 해시와 처리 배치 ID를 기록하여 재처리와 추적이 가능하도록 한다.
6. 월 단위 파티션 또는 날짜 인덱스를 적용하고 관측소·시각·항목 조합에 인덱스를 둔다.

권장 운영 테이블은 `station_metadata`, `sensor_metadata`, `observation_raw`, `observation_qc`, `qc_flag_history`이다. 원시값은 수정하지 않고 QC 결과와 보정값을 별도 컬럼/테이블에 저장한다.

### 2.2 기준정보·분석 정의

대상: `관측소_OBS ID POST_OCEANDB_v5.xlsx`, `정형데이터 테이블분석*.xlsx`, `정형데이터_관측항목_분석보고서.xlsx`.

작업: 엑셀 시트를 목록화하고 관측소·센서·항목 코드의 기준정보로 정규화한다. 컬럼 설명, 단위, 유효 범위, 코드값, 변경일을 데이터 사전으로 관리한다. `00.Old` 파일은 최신본과 대조한 뒤 폐기하지 말고 구버전으로 표시한다.

### 2.3 DB 프로시저와 SQL

대상: `분류/정형데이터/01.정형데이터/DB Procedure`의 SQL/TXT 파일.

작업: DBMS와 실행 환경, 입력·출력 테이블, 스케줄, 권한, 외부 의존성을 문서화한다. 운영 DB에 바로 실행하지 말고 테스트 DB에서 문법·성능·결과 건수를 검증한 후 마이그레이션 파일로 관리한다. 중복 프로시저와 날짜가 다른 `greenblue` 버전은 변경 비교표를 만든다.

### 2.4 현재 애플리케이션 샘플 CSV

`backend/sample_data`의 `station_metadata`, `sensor_metadata`, `observation_raw_tide`, `predicted_tide`, `qc_flag_history`, `quality_collection_report_sample`, `service_monitoring_log`, `daily_inspection_report`, `spring_tide_period`는 실제 원천이 아니라 개발 시드 자료다. 운영 적재 대상에서 제외하고, 스키마 검증·API 테스트용 fixture로 고정한다.

## 3. 비정형데이터 분류와 작업

### 3.1 정기 업무보고서

대상: `분류/비정형데이터/02.비정형데이터/2025`의 일일상황보고, 바다누리 서비스 모니터링, 대조기 모니터링, 주간 조위편차, 품질처리·수집률, 일일점검보고서.

작업: 날짜·보고서 유형·관측소·작성부서·버전을 파일명과 본문에서 추출한다. PDF/HWP/HWPX/XLSX를 텍스트와 표로 변환하고, 표의 수치(수집률·지연·장비상태·이상내용)는 가능하면 정형 보조 테이블에도 적재한다. 원본과 추출 결과를 함께 보존하고, 보고서 간 동일 사건·중복 첨부를 연결한다. RAG에는 본문 청크를 넣되 날짜·관측소·보고서 유형 필터를 반드시 함께 색인한다.

### 3.2 간행물·백서·뉴스레터·분석보고서

대상: 2018~2025 연간백서와 `04.요청자료/2차/6. 간행물`, `04.요청자료/2차/8. 용역사업 결과보고서`.

작업: PDF/HWP 원문에서 목차·장·절·페이지를 보존한 텍스트를 추출한다. 표와 그림은 캡션·페이지·원본 경로를 메타데이터로 붙이고, 스캔본은 OCR 품질을 표본 검사한다. 통계 수치는 출처 페이지와 단위를 보존한 별도 추출 테이블로 관리하며, RAG 답변에는 문서명과 페이지를 인용한다. 동일 보고서의 HWP/PDF/ZIP 사본은 대표본과 보조본 관계를 기록한다.

### 3.3 이미지·도면·그래픽

대상: PNG/JPG와 `FIG`, `그림`, `표` 폴더, AI/INDD/PSD 파일.

작업: 이미지 해시로 중복을 제거하고 촬영·작성 연도, 보고서, 페이지, 캡션을 연결한다. 이미지 자체는 원본으로 보존하되 OCR/캡션/객체 설명을 검색용 텍스트로 생성한다. AI/INDD/PSD는 편집 원본이므로 일반 RAG에 직접 넣지 않고 PDF/PNG 파생본과 제작 메타데이터를 제공한다.

### 3.4 DAT·TXT·XLS/XLSX 혼합자료

`DAT`는 확장자만으로 구조를 판단할 수 없다. 샘플 1%를 열어 인코딩, 고정폭/구분자, 헤더, 날짜 형식, 바이너리 여부를 판별하고 `텍스트형 정형`, `텍스트형 비정형`, `바이너리 미확인`으로 재분류한다. 텍스트형 관측자료는 정형 파이프라인으로, 설명·로그는 문서 파이프라인으로 보낸다. XLS/XLSX는 표 구조가 있으면 정형 보조 데이터로 추출하되 셀 주석·도형·서식에 의미가 있으면 원본 문서도 함께 보존한다.

## 4. 요청자료와 소스의 처리 경계

`04.요청자료`는 정형/비정형이 섞인 납품·요청 원본이다. 디렉터리 구조와 파일명은 증거자료로 보존하고, `3차/예측조위`의 TXT처럼 규칙적인 시계열만 별도 검증 후 정형 테이블로 복사한다. ZIP은 압축 해시, 내부 목록, 압축 해제본의 원본 관계를 기록한다. 자료를 `02.비정형데이터`로 무조건 복사하면 중복과 용량이 급증하므로 카탈로그에서 논리적 연결만 만든다.

`03.소스`의 JSP/JavaScript/Java/C#/DLL/EXE/DB 파일은 데이터셋으로 적재하지 않는다. 실행물은 격리 보관하고, 소스에서 확인되는 테이블명·API·스케줄·코드값만 시스템 이관 분석의 참고자료로 추출한다. 비밀번호, 연결 문자열, 운영 주소가 있는지 검색한 후 노출값은 비밀 저장소로 이전한다.

## 5. 공통 데이터 카탈로그와 품질 규칙

모든 파일에 다음 메타데이터를 부여한다: `asset_id`, 원본 경로, 논리 데이터셋, 데이터 분류, 업무 유형, 기준 연도/기간, 파일 형식, 크기, SHA-256, 생성·수집 시각, 출처 시스템, 개인정보/보안 등급, 처리 상태, 대표본 ID, 보존 기간.

처리 상태는 `미분류 → 목록화 → 품질검사 → 추출/변환 → 검증 → 적재/색인 → 운영승인`으로 관리한다. 실패 파일은 원본을 유지한 채 실패 사유와 재처리 횟수를 기록한다.

최소 품질 검사는 파일 무결성·중복·인코딩·날짜 범위·필수 컬럼·단위·관측소 코드 참조 무결성·행 수 변화·추출 텍스트 길이·OCR 신뢰도다. 보고서 수치와 정형 DB 수치가 충돌하면 자동 병합하지 말고 원천과 기준 시각을 표시해 검토 큐로 보낸다.

## 6. 권장 실행 순서

1. 대용량 원본을 변경하지 않고 전체 파일 카탈로그와 해시를 생성한다.
2. `01.정형데이터`의 월별 CSV 한 달을 선정해 스키마·시간대·QC 규칙을 확정한다.
3. 관측소·센서·항목 기준정보를 먼저 정규화하고 참조 무결성을 검증한다.
4. 업무보고서 1개 유형(일일상황보고)을 대상으로 PDF/HWP/XLSX 추출 및 RAG 검색 품질을 검증한다.
5. DAT 표본 판별 결과에 따라 정형/비정형 파이프라인을 분기한다.
6. 정형 DB 조회, QC 탐지, 문서 검색, 보고서 생성이 같은 `station_id`·기간·단위를 사용하는지 통합 테스트한다.
7. 검증된 파이프라인만 전체 연도와 요청자료의 선별 대상에 확장한다.

대용량 원본의 일괄 변환과 삭제는 카탈로그·백업·복구 검증이 끝난 뒤 별도 승인 절차로 수행한다.

## 7. 정형데이터 표준 처리 절차

정형데이터의 기준 흐름은 다음과 같다.

```text
원본 수집
  → 파일·배치 등록
  → 형식 및 스키마 검사
  → 표준 컬럼·코드·시간대 변환
  → 중복·결측·범위·참조 무결성 검사
  → 원시 영역 저장
  → QC 결과 저장
  → 서비스 집계·API·분석 제공
```

### 7.1 수집 및 배치 등록

`분류/정형데이터/01.정형데이터`의 월별 파일을 연도·월 순서로 수집한다. 파일을 받으면 원본 경로, 수집시각, 파일 크기, SHA-256, 제공 시스템, 대상 기간을 `ingestion_batch`에 등록한다. 같은 해시의 파일은 재처리하지 않고 기존 배치와 연결한다.

### 7.2 형식·스키마 검사

CSV 구분자와 인코딩을 자동 판별하고 헤더 존재 여부, 컬럼 수, 행 수, 파일 끝단 손상을 검사한다. 월별 파일 간 컬럼 변경을 비교하고, 새 컬럼·누락 컬럼·자료형 변경은 적재를 보류해 데이터 사전을 갱신한 뒤 승인한다. 대용량 파일은 메모리에 한 번에 올리지 말고 청크 단위로 읽는다.

### 7.3 표준화 및 정규화

관측소·센서·항목 코드로 기준정보를 조회해 표준 ID를 부여한다. 관측시각은 저장 기준을 UTC로 통일하고 원본 시각과 시간대는 별도 보존한다. 값은 숫자형으로 변환하며 단위와 소수점 규칙을 적용한다. 원본 행을 식별할 수 있는 `source_file_id`, `source_row_no`, `ingestion_batch_id`를 함께 저장한다.

### 7.4 품질검사와 QC 분리

다음 순서로 검사한다.

1. 필수키와 관측시각이 없는 행을 오류 격리 테이블로 보낸다.
2. 동일 관측소·센서·항목·시각의 중복을 찾아 대표 행과 중복 행을 구분한다.
3. 값의 물리적 유효범위, 급변, 고정값, 결측 구간, 시간 순서를 검사한다.
4. 기준정보에 없는 관측소·센서·항목 코드는 참조 오류로 분리한다.
5. 검증 결과를 `qc_flag_history`에 기록하고 원시값은 수정하지 않는다.

검사 통과 데이터만 서비스용 뷰와 집계 테이블에 반영한다. 오류 데이터도 삭제하지 않고 오류 유형·규칙 버전·처리시각과 함께 재처리 가능하게 보관한다.

### 7.5 저장·제공·재처리

원본 파일, 원시 적재 테이블, QC 결과, 서비스 집계 영역을 분리한다. 날짜 파티션과 관측소·시각 인덱스를 적용하고, API는 기본 기간·행 수 제한과 비동기 다운로드를 제공한다. 배치 실패 시 해당 배치만 롤백하고, 수정된 매핑이나 QC 규칙으로 동일 배치를 재실행할 수 있어야 한다.

정형데이터 배치의 완료 조건은 파일 행 수와 적재 행 수의 대조, 오류율 임계치 확인, 시간 범위 확인, 기준정보 참조 오류 0건 또는 승인된 예외 목록 생성, 샘플 API 조회 성공이다.

## 8. 비정형데이터 표준 처리 절차

비정형데이터의 기준 흐름은 다음과 같다.

```text
원본 수집·보존
  → 파일 식별·중복 제거
  → 문서 유형 판별
  → 텍스트·표·이미지 추출
  → OCR 및 추출 품질검사
  → 문서 메타데이터 부여
  → 청킹·임베딩·벡터 색인
  → 원문 근거와 함께 검색·답변
  → 색인 갱신·보존관리
```

### 8.1 원본 등록과 중복 처리

`분류/비정형데이터` 바로 아래의 업무 폴더와 `02.비정형데이터`를 스캔해 파일별 `asset_id`, 원본 경로, SHA-256, 확장자, 크기, 수정시각을 등록한다. 동일 해시는 대표본 하나를 정하고 나머지는 중복본으로 연결한다. ZIP은 압축파일 자체의 해시와 내부 파일 목록을 모두 기록하며, 원본은 삭제하지 않는다.

### 8.2 문서 유형별 추출

PDF는 텍스트 레이어를 먼저 추출하고 스캔 페이지에만 OCR을 적용한다. HWP/HWPX/DOCX는 본문·표·머리말·꼬리말을 분리 추출한다. XLS/XLSX는 시트명과 셀 범위를 보존하면서 표 데이터를 추출하고, 서식이나 도형에 의미가 있으면 원본 문서도 검색 대상으로 남긴다. PNG/JPG는 OCR과 캡션을 생성하고 원본 페이지·그림 번호를 연결한다. DAT/TXT는 인코딩·구분자·고정폭·바이너리 여부를 표본 검사한 뒤 정형 또는 문서 파이프라인으로 분기한다.

### 8.3 메타데이터와 문서 구조 보존

최소 메타데이터는 문서 유형, 제목, 기준 연도·기간, 보고서 날짜, 관측소, 업무 분류, 작성기관, 원본 경로, 페이지·시트·그림 번호, 보안등급이다. 본문은 문서명·장·절·페이지 경계를 잃지 않도록 추출한다. 날짜·관측소·보고서 유형은 검색 필터로 사용할 수 있는 별도 필드로 저장한다.

### 8.4 청킹·임베딩·색인

제목과 장·절 경계를 우선해 청크를 나누고, 표는 헤더와 단위를 반복 포함한다. 청크마다 `asset_id`, 페이지/시트, 기준기간, 관측소, 문서 유형, 추출 방식, 임베딩 모델 버전을 저장한다. ChromaDB에는 검증된 텍스트만 넣고, 임베딩 모델이나 청킹 규칙이 바뀌면 새 컬렉션으로 색인한 뒤 검색 품질을 비교한다.

### 8.5 품질검사와 답변 근거

추출 텍스트가 비어 있거나 지나치게 짧은 파일, OCR 신뢰도가 낮은 페이지, 표가 깨진 문서는 검토 큐로 보낸다. 대표 질문 세트를 만들어 검색된 문서가 질문의 기간·업무 유형과 맞는지 확인한다. AI 답변에는 문서명과 페이지/시트 근거를 포함하고, 근거가 없으면 답변을 생성하지 않는다. 보고서의 수치가 정형 DB와 다르면 양쪽 출처와 기준시각을 함께 표시한다.

### 8.6 갱신·보존·보안

새 파일은 해시와 문서 버전을 비교해 신규·수정·중복으로 분류한다. 수정 문서는 이전 색인을 비활성화하고 새 버전으로 교체하며, 이미 생성된 보고서가 참조한 버전은 보존한다. 운영 원본과 벡터DB 백업을 분리하고, 개인정보·접근제한 정보·운영 비밀이 포함된 문서는 권한 필터를 적용해 검색 결과에 노출되지 않도록 한다.

비정형데이터 처리 완료 조건은 원본-추출본 연결, 중복 처리 결과, 텍스트 추출 성공률, OCR 표본 검수, 필수 메타데이터 누락률, 대표 질문의 근거 문서 적중률을 기록하는 것이다.
