# UI/UX 개선과 2~8단계 연속 실행 계약

기준: 2026-10-06 KST. 실제 소스/API/파일 원장을 확인했다. 브라우저 자동화의
샌드박스 초기화 오류가 남아 있어 실제 픽셀 배치·클릭 검증 완료로 표현하지 않는다.
기존 지도·카드·표·하단 패널을 유지하고 데이터 의미와 업무 흐름을 개선한다.

| P1 | 상세 그래프는 현재 최대 500행만 표시 | 전체 기간 개요와 확대 구간 분리, 결측/센서 교체/사건/QC를 시간축에 표시 | 표본 페이지를 전체 기간으로 오인하지 않으며 미확정 시간대·교체일은 추정 표시하지 않음 |

| P2 | 접힌 메뉴와 아이콘 버튼의 키보드 접근성, 고정 높이 패널의 작은 화면 배치 미검증 | 버튼 의미/aria-current/포커스/색상 외 상태 표시, 반응형·확대·긴 관측소명 시험 | 좁은 폭·200% 확대·키보드만으로 주요 업무 완료 |

권장 업무 흐름: 종합 현황 → 관측소·기간 선택 → 이상 후보 구간 → 문서/사건 근거 →
담당자 검토 → Label → Dataset → 모델 비교 → 보고서 초안 → 승인/운영 기록.
이번 요청은 점검·개선안 정리이며 위 UI 항목 전체를 구현 완료했다고 보고하지 않는다.

## 현재 실행 증거와 선행 작업

- D:\share 추가 추출은 2,560개 처리 종료: 텍스트 추출·미검토 2,375,
  실패 98, OCR 필요 78, Office 잠금파일 제외 9. 추출 완료는 의미 검증/Embedding 완료가 아니다.
- D:\share 실제 파일과 기존 Embedding SHA-256 대조는 23:19 KST 기록에서
  3,000/3,791 문서 후보 처리 중. 기존 게시 내용 일치 1,555, 추출 후 미임베딩 1,224,
  추출 실패 131, OCR 58, 미색인 검토 22, 잠금파일 9, 부분 벡터 미게시 1.
  다른 분모의 추출 배치와 합산하지 않는다. 최신 수치는 원장에서 다시 읽는다.
- PID 17000 대조 worker 및 PID 16248 최종화/PID 28240 문서 연결 작업 생존 확인.
  문서 연결 로그는 234,000단위 스캔까지 증가했다. 스캔 수는 승인 연결 건수가 아니다.
- 실제 검색 재검증 `live-search-web-verification.json`은 PASS. 7종 문서 검색,
  원문 해시/SQL 텍스트/위치와 부정 필터 및 공통 조회 범위를 검사했다.
  전문가의 검색 관련성·인과 판단이나 UI 시각 검증을 대신하지 않는다.
- 벡터 20,976개 차이는 중단된 한 Excel 문서의 부분 업로드로 식별했다.
  SQL 게시되지 않은 상태를 유지하고 삭제하지 않는다.
- 최신 검증 폴더 포인터만 보고 웹에 게시하지 않는다. 필수 산출물·검증 완료까지
  마지막 완성 검증본을 서비스한다. 0/1단계의 미해결 계약도 병행 보완한다.

## 백그라운드 2~8단계 실행

| 단계 | 실제 실행 범위 | 다음 단계로 넘길 완료 증거 |
|---|---|---|
| 2 문서–사건–관측 | 현재 연결 배치 완료/검증 확인, 문서별 해시·쪽/시트·관측소·항목·사건·기간 후보와 월별 보유 구간 대조 | 근거 위치를 가진 연결표, 해소/충돌/근거 부족/미검토 구분, NULL 사유; 항목·센서·기간별 연결 수준을 별도 집계 |
| 3 QC·검토 | 적용 가능한 단위/시간대/규칙 버전만 제한 범위 실행, 원천 QC와 재검사 분리, 전후 행 정산 | 재현 실행 ID/규칙 버전/영향 구간/근거/담당 검토 큐. 담당 미승인은 그대로 유지 |
| 4 Label | 기압·염분·수온 등의 구간별 이상 후보와 원인 후보/불명을 구조화 | 후보/확인/반려/불명, 근거·검토자·이견 이력. 자동 후보를 정답으로 승격하지 않음 |
| 5 Dataset Registry | 고정 manifest·관측/문서/사건/Label 멤버십, 시간·관측소·사건 분할과 복제/미래 정보 누수 검사 | hash로 재현 가능, 탐색용/검토용/승인 평가용 구분. 미승인 자료로도 탐색 코드 검증 가능 |
| 6 모델 비교 | 업무별 기준선부터 제한 범위 평가하고 결과/시간/비용 기록 | 예측 persistence·24h seasonal·Ridge; 이상 탐지 QC/통계 기준 대비 LSTM Autoencoder 등 후보; 검색 현재 hybrid; 보고서 템플릿 대비 근거 기반 생성. 후보 선택과 운영 선정 구분 |
| 7 서비스 검증 | 실제 관측값·문서 인용으로 QC 지원/설명/보고서 초안 구현, 수정·반려·승인 역할 검증 | 사례별 입력→검색→생성→검토 이력 재현, 미지원 기능을 완료로 표시하지 않음 |
| 8 MLOps | 데이터/모델/검색 인덱스/프롬프트 버전, Registry·감시·재학습 후보·복구 구현과 시험 | 데이터/성능 변화 감시, 승인 배포와 롤백 시험, 운영 승인 상태와 실험 상태 분리 |

모든 파일 해소를 기다리지 않고 조건을 충족한 제한 범위부터 진행한다.
담당 승인·암호·누락 원문 등이 필요한 범위는 보류 이유와 필요한 입력을 기록하고
독립적으로 가능한 구현·시험을 계속한다. 실제 운영 승인이나 합격선을 임의 생성하지 않는다.
MDC 신규 비교는 수행하지 않는다. 원천·벡터·기존 검증본은 삭제하거나 덮어쓰지 않는다.

자동화는 같은 대화의 기존 작업 ID 1을 확장해 사용한다. 기존 배치 PID/시작시각,
OS lock, 원장 갱신을 대조한 뒤에만 재시작한다. 승인된 파일/실행 권한을 지키며
샌드박스 실패를 우회하지 않는다. 수동 명령 성공을 자동 실행 복구 증거로 쓰지 않는다.
사용자 요청에 따라 1분 주기로 진행을 알리되 실제 heartbeat 명령 성공 여부를 먼저 확인한다.
모든 단계의 구현·시험 완료 또는 가능한 독립 작업까지 외부 입력으로 막히면
정확한 완료/미완료·요청 조치 보고서를 남기고 반복 실행을 종료한다.
