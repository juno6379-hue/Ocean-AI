# 관측항목별 모델과 업무 메뉴 역할 계약

2026-10-07 사용자 지시 반영. 이 문서는 구현·평가 범위를 정의하며 모델 선정 또는 운영 승인이 아니다.

## 모델 담당의 책임

사용자가 업로드 중인 `D:\share\AI_anomaly_detection`을 기존 모델 인도자료 확인 대상으로 추가한다. 2026-10-07 첫 확인에서 해역별 `AI_QC_*_sea_no_update.py`에 TensorFlow `load_model`/`predict` 호출이 있으며 준실시간 QC 스크립트가 함께 보인다. 이는 추론 코드 존재의 증거다. 학습 코드·모델 파일·학습 데이터·성능 재현 여부는 별도로 확인한다. 두 차례 크기/수정시각 확인은 읽기 시점의 안정성 점검이며 업로드 전체 완료 증명이 아니다. 원문을 실행하거나 수정하지 않는다.

기존 MLOps 담당의 등록·승인·배포 준비도 점검에 **학습 소스 감사, 관측항목별 후보 비교, 재현 가능한 평가**를 추가한다. LSTM Autoencoder에 고정하지 않는다. 복잡도나 최신성만으로 우수 모델을 선언하지 않는다.

1. QC 담당이 품질관리 가이드북 원문의 시설·항목·검사·예외·단위·간격·버전을 목록화한다. 전체 목록과 세부 검토 완료 여부를 별도로 기록한다.
2. 모델 담당은 각 항목을 규칙 QC, AI 이상 탐지, 미래값 예측 업무에 대응시킨다. 적용 불가 또는 근거 부족도 누락 없이 사유를 남긴다.
3. 기존 조위 모델의 연도·입출력·학습기간·가중치·소스·평가를 확인한다. 보고서의 모델 설명만으로 학습 코드가 인도되었다고 판단하지 않는다.
4. 동일 데이터셋·시간 분할·사건 분할·단위·예측 지평에서 기준선과 후보를 비교한다. 미래정보와 중복 사건 누수를 검사한다.
5. 결과를 Label 담당과 교차 검토한다. 실제 운영 배포는 별도 승인·실행 검증·감시·롤백 조건을 따른다.

## 자료 구조에 따른 계약

### 재학습·자동 평가의 책임과 절차

모델·MLOps 담당이 재학습 실행기와 자동 평가·신구 모델 비교를 주관한다. 데이터 통합 담당은 원천→표준화→Parquet 변환과 행 수/결측/중복 정산 및 버전 고정, QC·Label 담당은 정상/이상 학습 근거와 제외 구간, 독립 검증 담당은 누수·재현·동일 조건 비교·배포/롤백 검증, UI 담당은 실행 상태·비교 결과·채택/보류 이유·승인 이력을 책임진다.

절차는 신규자료 검증 → Dataset 버전 고정 → 학습 전처리 → 후보 학습 → 기존 모델과 같은 고정 평가자료로 비교 → 독립 검증 → 담당자 승인 → 실제 배포 확인 → 감시·롤백이다. 학습 전처리의 fit 범위와 시간·사건·관측소 분할을 기록한다. 규칙 QC 판본 또는 입력 분포가 바뀌면 기존 성능과의 비교 가능성부터 검토한다.

재학습은 정기 일정·새 자료 충족·검증된 성능 저하/드리프트를 실행 조건 후보로 삼는다. 주기·최소 학습량·최소 개선폭·회귀 허용치·비용/지연 한계는 아직 확정하지 않았으며 임의로 운영 설정하지 않는다. 실행기에는 중복 실행 방지 lock, 멱등 작업 ID, 실패/재시도 이력, 데이터·코드·환경·모델 hash, 학습/평가 receipt가 필요하다.

예측 평가는 항목·단위·예측 지평별 MAE/RMSE와 기준선 대비 개선, 이상 탐지는 Precision/Recall/F1·오경보·사건 탐지 지연으로 분리한다. 결측 복원은 별도 마스킹 평가를 사용한다. 항목 간 단위가 다른 MAE를 합산하거나 분류 accuracy를 예측 정확도와 같은 값으로 표시하지 않는다. 후보 학습 성공·평가 수치 개선·운영 승인·실제 배포 성공은 서로 다른 상태다.

현재 코드의 재학습 API는 실행기가 없어 501이며 운영 배포/롤백은 실제 runtime 검증이 없어 차단된다. 이 절차 정의는 자동화 구현 완료가 아니다. 새 모델이 비교시험을 통과해도 자동으로 원천 QC·Label·운영 모델을 덮어쓰지 않는다.

- 조위: 기준면·조화 예측·듀얼 센서·설치 방식·해역과 교체 구간을 확인한다.
- 수온·염분: 단위·수심·전도도 관계·교정/세척·센서 사용기간을 확인한다.
- 기상·파랑·유속/유향 등: 가이드북의 실제 대상 목록에 맞춰 평균화·방향·관측주기·관련 항목 검사를 명시한다.
- HF-radar: 방사 유속과 합성 해류의 단계, 격자·좌표·U/V·관측소 조합·품질지표를 구분한다. 가이드의 검토되지 않은 세부 규칙은 미확정으로 남긴다.
- 동일 관측소·시간·수심·단위의 대응을 입증하지 못한 항목을 다변량 모델에 묶지 않는다. 단변량 평가부터 수행할 수 있다.
- 과거 CSV는 장기 예측·통계, 월별자료는 지정된 기준 관측자료로 구분하고 중복기간·개정 이력을 기록한다.

## UI 반영 원칙

기존 지도·요약·카드·관측 표와 OSM을 보존한다. 각 메뉴에 목적과 다음 업무를 간결하게 안내한다. 관측기간, 시설 운영 기준일(2026-07-31), 집계 확인시각, 사건 발생시각, 문서 작성/가용시각은 별개다.

등록 코드 수·자료 보유 시설 수·해당일 운영 시설 수를 구분한다. 수집률은 확인된 기대 건수와 제외 정책이 있을 때만 산출한다. 관측 공백, 자료 미수령, 미적재, 조회 실패를 구분한다. 미구현 행동과 미확정 수치를 실행 성공·0·정상으로 표시하지 않는다.

관련 API와 원문 근거가 확인된 지표만 실제 숫자를 표시한다. 미구현은 별도로 표시하고 작업 목록에 남긴다. 요약 클릭은 동일 시설·항목·기간 조건의 상세·QC·보고서로 이어져야 한다.

### 검증 역할의 연결 단위

관측소 ID → 장비/물리 센서 ID → 사용 유효기간 → 문서 ID·쪽/표 → Parquet 파일·행/구간 → 청크 ID·원문 hash·Embedding 계약 → API 질의 → UI 표시를 같은 원천·항목·기간으로 추적한다. 이름이 같거나 벡터 검색 결과가 있다는 이유만으로 동일성을 승인하지 않는다.

각 연결은 `PASS`, `CONFLICT`, `MISSING`, `NOT_VERIFIED`로 기록한다. 요청 범위·검사 분모·표본 여부·확인시각·예상/실제 ID·NULL 사유·담당 역할을 남긴다. 데이터 참조·행 수·hash 정합성과 문서 의미의 사실 확인은 별개 검사다. 센서·기간이 미확정이면 나머지 연결의 부분 통과를 보존하되 전체 연동 완료로 표시하지 않는다.

### 공통 완료 조건

- 가이드 대상 목록과 규칙·자료·모델 적용표가 행 단위로 대응하고 누락 사유를 확인할 수 있다.
- 업무편람/절차 원문의 위치와 메뉴별 행동·권한을 대조한다.
- 동일 질의에서 DB·Parquet·API·UI의 범위·분모·판정 상태를 대조한다.
- QC ↔ 모델 ↔ Label, API ↔ UI의 교차 검토와 반례 시험을 기록한다.
- 브라우저 클릭·시각 검증이 실행되지 않았다면 빌드 성공과 분리해 미검증으로 보고한다.
