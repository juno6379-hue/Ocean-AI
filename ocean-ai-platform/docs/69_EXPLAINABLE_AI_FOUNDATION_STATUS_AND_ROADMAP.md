# 설명 가능한 해양관측 AI: 현재 구축 상태와 다음 단계

기준: 2026-10-06 실제 PostgreSQL·파일 manifest·처리 원장 확인.
이 문서는 구현, 실제 적재, 검증, 승인, 운영을 구분한다. 기존 문서의 과거 수치는
현재 상태를 대신하지 않는다. 진행 중 배치 수치는 아래 확인 시점의 스냅샷이다.

## 2026-10-06 운영 복구 후 갱신 안내

아래 최초 점검 표의 검색 서버 중단·부분 벡터 조사·추출 진행 상태는 과거 확인 기록이다.
이후 Chroma 검색 복구 및 실제 검색·원문 검증이 PASS로 확인되었고, 추가 벡터
20,976개는 한 Excel 파일의 부분 업로드로 식별했다. D:\share 추가 추출은
2,560개 정산을 마쳤으나 예외와 의미 검토·임베딩 작업이 남아 있다.
최신 진행과 UI/UX 점검, 2~8단계 실행 계약은
[70번 운영 문서](70_UI_UX_AND_BACKGROUND_EXECUTION.md)를 참조한다.
서버 생존과 실행 중 배치의 현재 상태는 각 실행 시 다시 확인한다.

## 1. 목표와 저장 역할 확정

목표는 관측값을 모으는 데서 끝나는 것이 아니라 **관측값 → 품질상태 → 관련 사건 →
원인 후보 → 문서 근거 → 담당자 판단 → 재현 가능한 학습/평가 자료**를 연결하는 것이다.
검색된 문서가 있다는 이유만으로 원인이나 센서 사용기간을 확정하지 않는다.

| 계층 | 보존/관리 내용 | 원칙 |
|---|---|---|
| 원문·원천 | CSV, PDF, HWP/HWPX, XLS/XLSX, DOCX, ZIP 등 | 원문과 체크섬·위치·수집 이력 보존 |
| Parquet 레이크 | 대용량 관측값, 파싱 결과, 표준화 버전, QC 결과, 학습 특징 | 원천/표준/분석층과 manifest 분리; 대용량 분석·학습의 본체 |
| PostgreSQL | 식별자 대응, 기간, 장비/센서 이력, 사건, 문서 계보, 검토·승인, Label/Registry | 업무 관계·상태·운영 이력의 기준 저장소 |
| Vector DB | 문서 청크의 임베딩과 검색용 필터 | 원문/문서/청크 ID로 돌아가는 검색 색인; 사실 승인 저장소가 아님 |
| 처리 원장 | 파일별 처리·실패·제외·재시도·정산 | 총량·분모·미처리 이유를 숨기지 않음 |
| 서비스/AI | 통합 조회, QC 지원, 근거 검색, 설명, 예측, 보고서, 검토 | 같은 버전·같은 연결키·같은 승인 상태 사용 |

**관측값 전체의 PostgreSQL 복제는 필수 완료 조건으로 두지 않는다.**
사용자가 정리한 Parquet 중심 구조를 기준으로 하며, PostgreSQL 관측값 적재는
최근 자료·빈번한 조회·운영 트랜잭션 등 필요 범위의 선택적 제공 계층으로 설계한다.
전체 PG 복제가 끝나야 다음 단계로 갈 수 있다는 이전 추진 조건을 대체한다.
실제 관측값을 읽는 API와 계보·검토 상태의 연결은 반드시 검증한다.

현재 파일 레이크는 NTFS 로컬 저장이다. S3/MinIO Object Storage가 이미 구축됐다고
표현하지 않는다. 향후 객체 저장소로 바꿔도 원천 식별자와 manifest 계약을 유지한다.

## 2. 현재 위치: 데이터 기반과 일부 서비스 연결, 승인 학습데이터는 미완료

| 영역 | 실제 확인한 것 | 아직 완료되지 않은 것 |
|---|---|---|
| 정형 자료 변환 | 월별 기준 2023-01~2026-07, 93개 관측소 코드, 151개 항목 코드, 43개월, 1,017,630,666행 | 표준 항목 의미 확정, 단위/시간대/센서 전체 확정, 전체 QC 승인 |
| 추가 원천 | GD_OBS_BU/GD_OBS_VBU/GR_OBS_ST 각 33개월, 총 99파일·907,650,042행 변환 정산 | 기준 월별자료와 동일 관측임을 증명하지 않고 자동 병합하지 않음 |
| 과거 시계열 | legacy와 원천 보존 Parquet 존재, 명시적 raw 정산 자산 일부 조회 가능 | 2011~2021 전 관측소·항목 정산/연속성/웹 조회 완료 아님 |
| 웹 연결 | 대시보드·현황·상세가 공통 실측 API 사용; 원천/기간/항목/수심/문서 근거 표시 | UI 자동 시각검사 실패, 다른 AI 업무 화면까지 이 API로 전부 전환한 것은 아님 |
| RDB 연결 | `lake_serving` 계보 6,479개·월별 검증 기록 66,421건 실제 적재 | 공통 의미 식별자·기간·사건 연결 전수 승인 |
| 비정형 처리 | 원문 보존·여러 형식 파서·문서/표/이력/사건 후보 추출 | 전체 추출 성공·전문가 검토·기간별 사실 확정 |
| 문서 색인 | `document_index` 1,600개 문서·245,036개 청크 | 물리 센서/사건/관측기간의 전용 연결 컬럼 채우기 |
| Embedding | 활성 SQL 청크 244,162개와 Chroma 메타데이터 ID 전부 일치 | 검색 서버 재가동, 추가 20,976개 벡터 ID의 게시 상태 정산, 실제 검색 재검증 |
| QC | 일부 규칙 파일럿·이상 후보와 문서 비교, 미확정 조건별 검증표 | 전체 범위 정밀 QC, 당시 규칙/현재 재검사 구분, 담당 승인 |
| Label | 스키마/검토 흐름 일부 구현 | `ai_label` 및 `label_review_snapshot` 실제 적재 0 |
| Dataset Registry | 평가 준비도 스냅샷·프로토콜 각 4건 | public Registry/멤버십 0, 승인 평가 멤버 0 |
| AI 모델 | 학습/평가 코드와 일부 파일럿 이력, 임베딩 모델 계약 | 업무별 비교 후 선정한 운영 모델, `model_registry` 적재 0 |
| 보고서 자동화 | 문서/보고서 API·템플릿/생성 흐름 일부 | `ai_reports`, `report_registry`, `report_generation_history` 실제 적재 0 |
| Human-in-the-loop | 검토·승인 API와 권한 검사 구현 일부 | 운영 사용자 설정, 검토 큐 처리, `approval_history` 실제 기록 0 |
| MLOps | Registry/재학습 스키마·코드 일부 | 등록 모델·배포 승인·성능/드리프트 감시·롤백 실증 |

두 정형 범위의 합계는 원천별 보유 행 합계이지, 중복 제거한 고유 관측 건수가 아니다.
151개는 원천 항목 코드 수이며 표준 관측 항목 151종이라는 뜻이 아니다.
`ai_reports`는 우리가 만든 AI 보고서 테이블이며 현재 0건인 것이지 미조회가 아니다.

### 실제 연결 수준의 증거

`document_index` 전용 컬럼 기준:

- 전체 청크: 245,036; 관측소 ID가 있는 청크: 111,854.
- `related_sensor_id`, `event_id`, 시작·종료 관측기간이 모두 채워진 청크: 각각 0.
- 다른 후보 저장소에는 운영 사건·기간 후보가 있다. 위 0을 모든 스키마에 근거가
  전혀 없다는 뜻으로 해석하지 않는다. 문서 검색 색인과의 통합 연결이 미완료인 것이다.
- `foundation.operation_event` 16건, `foundation.document_record` 456건,
  `foundation.document_location` 783건, 장비 후보 연결 1,575건.
- `evidence_eval.assertion` 15,332건, `period_candidate` 352건,
  `temporal_candidate` 0건. 후보 생성과 승인된 기간 연결을 구분한다.
- 업무별 평가 준비 스냅샷 4개는 모두 BLOCKED, 승인 멤버 0.

### Embedding은 저장됐지만 검색 운영 상태는 별도

활성 계약은 `mxbai-embed-large:latest`, digest 고정, 1,024차원,
컬렉션 `ocean_semantic_19894990347ab79b`이다. 이 선택은 **문서 임베딩 모델 설정**이며
예측·이상 탐지·보고서 생성 모델의 업무별 선정 완료를 뜻하지 않는다.

Chroma SQLite를 읽기 전용으로 대조한 결과:

| 항목 | 건수 |
|---|---:|
| 활성 SQL 임베딩 ID | 244,162 |
| 활성 컬렉션의 저장 메타데이터 ID | 265,138 |
| 일치 | 244,162 |
| SQL에는 있지만 벡터 메타데이터에는 없음 | 0 |
| 벡터 메타데이터에는 있지만 SQL에는 없음 | 20,976 |

추가 20,976개는 미게시/실패/진행 중 잔여 여부를 조사해야 한다. 고아 데이터로 단정하거나
삭제하지 않는다. 이 대조는 HNSW의 실제 벡터 검색 무결성 검증이 아니다.
현재 `127.0.0.1:8001` heartbeat는 연결 실패했다. 10월 2일 검색 성공 기록을 현재
가동 성공으로 대신하지 않는다. 처리 원장의 RUNNING 표시도 프로세스 생존 증거가 아니다.

기존 문서 배치: 대상 4,955개, 성공 고유 문서 1,600개, 중복 1,512개,
미처리 1,697개, 실패 145개, RUNNING 표시 1개. 중복을 성공 문서 수에 더하지 않는다.
별도의 D:\share 추가 추출 배치는 확인 시점 2,068/2,560 처리:
텍스트 추출·미검토 1,883, 실패 98, OCR 필요 78, Office 잠금파일 제외 9.
두 배치의 대상/단계가 달라 건수나 완료율을 단순 합산하지 않는다.

## 3. 공통 연결키: 설계 원칙과 남은 구현

아래는 통합 계약으로 정립할 키다. 동일 이름의 실제 테이블이 모두 존재한다는 뜻은 아니다.

| 연결 대상 | 보존할 키·시간 | 검증 원칙 |
|---|---|---|
| 원천 | `source_system`, `source_asset_id`, SHA-256, 파일/행 위치 | 원천코드와 표준코드 별도; 파일 이동은 실제 위치 매핑으로 처리 |
| 관측소 | 원천 관측소코드, `station_id`, 대응 근거·유효기간 | 이름 유사성만으로 합치지 않음 |
| 항목 | 원천 항목코드, `item_id`, 단위/관측방법/수심 | 전도도와 염분, 서로 다른 조위계 방식 등 자동 통합 금지 |
| 장비/센서 | `equipment_id`, `physical_sensor_id`, `deployment_id`, 사용기간 | 논리 채널 ID를 물리 센서로 승격하지 않음; 일련번호·설치/회수 근거 필요 |
| 시간 | 관측시각, 원천 시간대, 수신시각, 수집/적재시각, 유효기간, 판단 기록시각 | 수집일·보고일·개소일·센서 설치일 구분; 일/월 정밀도 보존 |
| 사건 | `event_id`, 발생/발견/조치 기간, 유형, 상태 | 같은 관측소라도 시기가 다르면 직접 원인으로 연결하지 않음 |
| 문서 | `document_id`, 버전/해시, `chunk_id`, 쪽/시트/행/문단 | 문서의 주장과 검토 결론을 별도 기록 |
| QC | `qc_run_id`, 규칙/가이드 버전, 원천 flag, 재검사 flag, 검토 상태 | 당시 판정과 현재 재검사 분리; 규칙 후보를 승인 규칙으로 오인 금지 |
| 학습/평가 | `label_id`, `dataset_version`, 멤버십, 분할/특징 버전, 승인 | 근거/관측/문서/모델 실행까지 역추적 가능 |

미확정 키는 NULL로 남겨 원천 조회와 검토를 계속한다. 각 업무의 학습/배포 조건에서
필요한 키만 검증한다. 검색 실험까지 모든 센서 메타데이터 확정을 기다리게 하지 않는다.

## 4. 목표 학습데이터의 단위

관측소·항목·센서/채널·시간창을 한 샘플로 삼되 다음 요소를 분리해 연결한다.

1. **관측:** 원천 파일/행 ID, 시계열 구간, 결측/중복, 표준화 버전·변환 기록.
2. **품질:** 원천 QC, 자동 검사 결과, 적용 규칙/버전, 유효 건수와 검토 상태.
3. **사건:** 센서 교체·점검·교정·통신 장애·처리 변경 등 사건과 적용 기간.
4. **근거:** 원문·청크·페이지/시트/행, 발췌, 주장, 충돌/지지 관계.
5. **판단:** 확인 원인과 원인 후보, 검토자·검토시각·승인/반려·변경 이력.
6. **학습 계약:** 업무, label, 데이터 버전, 멤버 목록, 학습/검증/시험 분할,
   사용 가능 정보의 기준시각, 모델/프롬프트/검색/특징 버전.

자동 튐값 판정은 '이상 후보' label이며 '센서 고장' 정답이 아니다.
원인 미확정도 유효한 상태로 보존한다. 보고서의 단순 언급이나 유사도 점수는
인과관계의 확신도로 사용하지 않는다.

예측 평가에서는 예측 시점 이후에 작성된 장애 보고서·교정 결과를 입력에서 제외한다.
사후 원인 설명에서는 사용할 수 있지만, 사후 정보를 썼음을 명시한다. 같은 사건,
중복 문서, 같은 시계열의 복제 원천이 학습과 시험에 나뉘어 들어가지 않도록 한다.

1~3을 진행하면서 검색 서비스와 소규모 평가 세트 준비를 병행한다. 모든 파일의
완벽한 해소를 기다리는 대신, 검증된 제한 범위를 먼저 고정하고 미해결 범위를 명시한다.
과거 2011~2021 자료의 정산과 확대도 별도 범위로 계속하며 월별 기준자료와 섞지 않는다.

## 6. 업무별 평가·Human-in-the-loop·지속 개선

| 업무 | 우선 평가할 것 | 사람의 역할 |
|---|---|---|
| 데이터 통합 | 원천 행 정산, 코드 대응 정확도, 시각/기간 충돌, 연결 누락 | 대응·기간 주장 승인, 충돌 해소 |
| QC 지원/이상 탐지 | 사건 단위 정밀도·재현율, 정상 오탐, 지연, 관측소/항목별 차이 | 이상 후보의 실제 의미와 원인 검토 |
| 지식검색 | 근거 Recall@k·순위 적합도, 관측소/기간/문서 버전 필터 준수 | 정답 근거와 관련성 평가 |
| 설명 | 인용 지지 여부, 시간 일치, 원인 과장 여부, 불명 응답의 적절성 | 근거로 확정 가능한 결론과 후보 구분 |
| 예측/통계 | 시간 순서 검증, 예측지평별 MAE/RMSE 등, 결측/센서 교체별 성능 | 업무 허용 오차와 사용 제한 확정 |
| 보고서 자동화 | 수치 재계산 일치, 인용 정확도, 필수 항목, 수정량·검토시간 | 최종 책임자의 수정·승인 |
| 운영/MLOps | p50/p95 처리시간, 실패율, 자원/호출 비용, 데이터/모델 변화 | 재학습·승격·롤백 승인 |

지표 이름만 등록한 상태를 평가 완료로 보지 않는다. 각 업무의 허용 기준은 실제
기준모델 결과와 담당자의 요구를 반영해 수치로 승인한다. 임의의 95% 정확도 등을
운영 합격선으로 꾸며 넣지 않는다. 검토 결과는 재학습 후보로 돌아가되 자동으로
정답 label이나 새 운영 모델로 승격하지 않는다.
