# 동일 기준시각 운영 진단과 가상 품질 시험

기준일: 2026-10-09. 관측현황의 동일 기준시각 자료 흐름 판정과 가상 이상탐지·품질 프로세스 시험을 구현했다. 실제 승인 계정은 사용자 지시에 따라 실제 업무 수행 시 설정한다. 가상 시험의 승인·복구 기록은 운영 승인이나 원천 사실 확정으로 사용하지 않는다.

## 실제 화면의 판정

`2026-07-09 15:41:20` 기준 GD 월별 원천의 61개 관측소는 최근 24시간 자료 흐름에서 정상 58, 주의 2, 이상 1로 산정됐다. 전체 보유 원천 행 수 7,126,689와 실제 값·그래프·사진 연결은 유지된다. 주의는 마산·옹진소청초, 이상은 이어도이며, 해당 채널의 추정 관측 격자 대비 자료 공백이 원인이다. 이 판정은 장비 고장이나 승인 QC 확정이 아니다.

관측소 상세의 ‘판정 근거’에서 채널별 최근 시각·지연·추정 간격·유효 값·결측·중복 충돌·원문 QC와 점검 이력을 확인한다. 상단 집계와 목록 운영상태 필터는 동일 판정과 정책 해시를 사용한다. 실제 수신 수집률은 예정 관측건수와 수신 이력이 없어 `null`이다. 원천 시각에서 계산한 ‘참고 자료 채움’과 수집률을 구분한다.

화면에서는 이 별도 자료 보유 지표를 **수집률 (추정)**으로 명시해 빈 숫자 대신 제공한다. 분자는 최근 24시간의 보유 고유 관측시각 수, 분모는 같은 채널의 원천 시각에서 추정한 관측간격·위상으로 만든 격자 수다. 실제 수신 여부나 승인 수집률을 확정하지 않는다. 채널별 간격·위상을 검증하지 못한 경우 수치 대신 계산 불가와 제외 범위를 표시한다. 전체·해역·관측망 범위의 비율은 채널 격자 분자·분모를 합산하며 관측소별 비율을 단순 평균하지 않는다.

해역·관측망·운영상태·검색을 적용한 같은 관측소 집합이 상단 집계, 지도, 목록, 바로 선택, 상세 선택에 사용된다. 분류는 7월 문서 대조를 포함한 DB 기준정보의 정확한 원천 코드로 비교한다. 필터 범위 밖 관측소의 이전 상세를 남기지 않는다. 필터 변경 시 같은 원천·기간·기준시각 전체 응답을 다시 읽지 않아 즉시 반영하며, 원천·기간·기준시각 변경 시에는 새 응답 검증 후 표시한다.

## 개발 판정 정책

- 범위는 `(기준시각−24시간, 기준시각]`, 이전 7일은 관측 간격·위상 변경 비교에 사용한다. 원문 시계에 시간대를 임의 적용하지 않는다.
- 원천·관측소·항목·형식 보존 수심별로 집계한다. 같은 시각의 원문 중복과 값 충돌을 보존한다.
- 최소 12개 고유 시각, 양의 간격 최빈값 점유율 80% 이상, 단일 위상과 이전 구간 일치를 확인한 경우에만 격자 분모를 추정한다. 불확실한 분모는 `null`이며 주의 사유를 남긴다.
- 자료 채움·유효 값 비율 99% 이상을 정상 기준, 90% 미만을 이상 기준으로 사용한다. 지연 주의는 `max(3×관측간격, 300초)`, 지연 이상은 `max(10×관측간격, 1800초)` 초과다.
- 명시적으로 검증한 코드북에만 원문 QC 의미를 적용한다. 고유 관측시각 기준 BAD 또는 BAD+MISSING 비율이 10% 이상이면 이상, BAD/MISSING/SUSPECT가 있으면 최소 주의다. NULL·공백과 미매핑 코드는 정상으로 바꾸지 않는다.
- 점검·사건·QC 이력은 기준시각 이전에 알려진 판본, 원문 시간대와 정확한 센서·항목 연결을 확인한다. 복구는 정확히 연결된 사건만 정리하며 실측 지연·결측 판정을 낮추지 않는다.
- 관측소는 최악 채널의 상태를 따른다. 일부 채널이 미평가이면 전체 정상으로 숨기지 않는다. 정책은 개발용 미승인 기준이다.

실제 PostgreSQL의 점검·운영·품질보고·QC 이력·사건 테이블을 읽기 전용으로 확인한 결과 등록 행은 모두 0이었다. 빈 원장, 없는 테이블, 쿼리 실패를 구분한다. 현재 장비 상태를 과거 시각의 상태로 재사용하지 않는다.

## 가상 시험

관측현황 하단 ‘운영상태·QC 가상 시험’에서 같은 기준시각의 시나리오를 실행한다. 정상, 지연, 결측, 원문 QC 이상, spike, 수온 drift, 염분 drift, persistence, biofouling 후보, 조위 residual, 점검, 복구, 미래 근거 제외, 중복 값 충돌, 관측 간격 변경의 15종이다.

가상 코드·단위·센서 구간·기준면·UTC 시계·QC 코드북·가용 시각은 시험 계약에 명시한다. 이 선언은 실제 원천의 미확정 시간대·물리 사실을 해결한 것으로 해석하지 않는다. 합성 값과 센서 기준값을 train/calibration/test로 분리하고 시험 구간에만 이상을 주입한다. 표시되는 가상 그래프는 주입한 값과 일치한다.

1. 실제 운영 진단 공통 함수가 관측 지연·공백·QC·점검 사건을 판정한다.
2. 실제 12종 Rule QC 엔진 중 이 시계열의 6개 설정(WT/ER/GR/GD/SP/DE)을 실행한다. 초기 윈도우 부족 등 미평가를 보존한다. 위치·연관 항목·기준 통계·전압이 필요한 나머지 규칙은 기존 규칙별 시험에서 검증한다.
3. 실제 이상탐지 엔진에서 분리된 학습·보정으로 적합하고 시험 구간을 평가한다. SPIKE/PERSISTENCE/DRIFT/TIDE_RESIDUAL/BIOFOULING_CANDIDATE/SENSOR_DEGRADATION_CANDIDATE는 후보이며 원인 확정이나 최종 QC를 쓰지 않는다.
4. 실제 Fusion이 Rule/AI/Metadata/Operation/RAG의 시험 근거를 결합한다. score는 근거 지지 점수이며 이상 확률이 아니다. Rule과 AI가 다르게 판단한 경우 `REVIEW_CONFLICT`를 보존한다. RAG는 외부 검색을 실행하지 않고 고정된 가상 문서 근거로 연결 경계를 시험한다.
5. 실제 영속 workflow 서비스를 매 실행마다 폐기하는 메모리 DB에서 검증한다. PENDING 중 후속 단계 중지, 미승인 재개 차단, reviewer 권한, 반려 후 재개 차단, 오래된 revision 차단, 승인 후 멱등 재개를 확인한다. 시험 reviewer/operator를 실제 인증 설정에 등록하지 않는다.

가상 출력에는 `source=SIMULATION`, `is_simulation=true`, `approved=false`, `production_completed=false`와 결과 SHA-256을 남긴다. 실제 원천·승인·dataset·registry·배포 테이블에 쓰지 않으며 61개 실제 집계와 혼합하지 않는다. 메모리 SQLite는 가상 gate 시험에만 사용하고 운영 DB는 PostgreSQL이다.

## API와 검증

`GET /api/operation-simulation/scenarios`, `POST /api/operation-simulation/run`을 제공한다. 요청은 `{scenario_id, as_of_day, as_of_time}`만 받으며 loopback·2 KiB 제한과 미등록 필드 거부를 적용한다. 사용자 공급 행·경로·actor·실제 승인·배포 요청은 받지 않는다.

세 에이전트가 운영 진단, 날짜별 증거, UI를 나누어 구현하고 센서·QC 판본 경계와 실제 응답 계약을 교차 검토했다. 부모는 실제 143개 Parquet를 Arrow로 별도로 읽어 11개 채널의 최근 24시간·이전 7일 집계를 대조했다. 운영 원장 읽기 전용 확인, 실제 응답 전수 UI 계약, 가상 통합 시험 및 전체 회귀 결과는 [검증 기록](33_OPERATION_DIAGNOSTICS_AND_SYNTHETIC_QC.json)과 [현재 상태](current_status.json)에 기록한다.

이 기능은 개발 시험 프로세스를 검증한다. 운영 성능 수용, 실제 원천 코드북·시간대·센서 기간 승인, 실제 모델 registry 등록과 업무별 배포는 해당 근거와 승인 후에 진행한다.
