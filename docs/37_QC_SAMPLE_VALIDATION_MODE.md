# 37. QC 샘플 검증 모드

기준: 2026-10-09. 사용자가 빈 운영 화면 대신 정상·지연·결측·Spike의 상세 근거와 검토 처리를 직접 확인하도록 요청했다. [운영 QC 검증](36_QC_OPERATIONAL_DASHBOARD_EXECUTION.md)의 자동 테스트 fixture를 화면에서 확인할 수 있는 별도 기능으로 확장한다.

## 데이터와 실행 경계

샘플 페이지는 `/qc/sample`이며 운영 QC는 `/qc`에 유지한다. 샘플 관측소·센서·시각·원천 계약·검토자는 가상이다. Evidence는 합성 정의와 기존 엔진의 계산 보고서이며 실제 점검·운영·문서 이력으로 표시하지 않는다. 고정 샘플 시각과 threshold·판본을 화면에 명시한다. 정상·지연·결측·Spike 판정은 기존 `qc_rule_engine.execute_rules`의 계산 결과를 사용한다.

`QC_SAMPLE_ENABLED=false`가 기본이다. 명시적으로 활성화한 development/test/local 환경에서만 API가 동작하며, 다른 환경은 404다. 검토 서버 8010에서만 활성화한다. canonical 8000/5173, 문서 서버 8001, 개발 시험 모델 8011은 보존한다.

각 페이지 진입은 독립 샘플 세션을 만든다. 세션·검토 이력은 서버 프로세스 메모리에만 저장하고 운영 PostgreSQL을 읽거나 쓰지 않는다. 세션 token은 샘플 전용 header에서만 사용하며 실제 operator 인증으로 사용할 수 없다. 브라우저 새로고침은 새로운 세션이고 화면의 ‘샘플 새로고침’은 현재 세션을 재조회한다. 서버 재시작은 메모리 이력을 제거한다. 세션 만료·용량 제한·초기화를 제공한다.

결측은 샘플 예정 슬롯의 빈값과 gap으로 표시하고 그래프를 보간하지 않는다. 지연은 샘플 관측·수신 시각의 차이와 marker를 유지한다. 통계 참고값은 학습된 AI 모델이나 승인된 정상 기대값으로 표시하지 않는다. 실제 AI 학습·추론·serving·Final QC 수정·운영 승인은 실행하지 않는다.

## 담당자 처리

샘플 검토는 PENDING에서 멈춘다. 검토 의견·보류·반려·승인·재개를 시험할 수 있으며 승인 후 재개해야 COMPLETED가 된다. 각 요청은 세션 token, 대상 사례, 현재 revision, 추천 SHA, request key를 검증한다. 잘못된 대상·이전 revision·변경된 SHA는 차단하고 동일 request key는 중복 처리하지 않는다. 이 동작은 샘플 상태 기계의 검증이며 실제 원장의 담당 승인이나 candidate Final QC gate 완성을 뜻하지 않는다.

## 네 가지 사례와 분모

고정 합성 시간창은 **2026-07-09 14:40:00~15:40:00 +09:00**, 조회 기준은 **15:41:20 +09:00**이다. 이 offset은 시험 자료에 명시한 값이며 실제 원천 시간대 승인으로 사용하지 않는다. 각 시계열은 60초 간격의 61개 예정 슬롯이다.

| 사례 | 선택 발생시각·입력 | 실제 엔진 계산 | 화면·검토 시험 |
|---|---|---|---|
| 정상 | 15:30 · 19.750002℃ · 수신 +1초 | 정상 1 | 원문·시계열·Rule 근거 확인, 의견 저장 후 PENDING 유지 |
| 수신 지연 | 15:30 관측 · 15:38 수신 · 480초 지연 | DE 허용 300초 초과, Suspect 3 | 8분 지연 marker·관측값 유지, HOLD 후 중지 |
| 결측 | 15:09/15:10/15:11 예정 슬롯 값 NULL·수신 없음 | 명시된 샘플 sentinel -999를 Rule 입력으로 사용, ER 결측 9 | 수신 58/예정 61, 그래프 공백·보간 없음, 확대·REJECT 후 차단 |
| Spike · 범위 초과 | 15:10 · 45℃ | SP 허용 변화 1 초과는 Suspect 3, GR 상한 40 초과는 BAD 4 | 두 Rule를 분리 표시, APPROVE에서도 중지, RESUME 후 합성 초안 완료 |

상단 KPI와 Flag 도넛은 **대표 사례 4건** 기준으로 초기 정상·주의·BAD·결측이 각 1건/25%다. 분별 추이는 **61분×4개 예정 슬롯**, 행렬은 **각 시계열의 61개 예정 슬롯** 기준이다. 전체 예정 244개 중 수신 241개·결측 3개이며, 대표 사례의 25%를 전체 관측행의 비율로 해석하지 않는다. 검토 대기는 PENDING만, 처리 완료는 COMPLETED만 집계한다. 보류·반려·승인 후 재개 대기는 목록의 개별 상태에서 확인한다.

기존 12종 Rule에 244개 슬롯을 입력해 2,928개 결과를 만든다. WT/ER/GR/GD/SP/DE는 합성 계약과 설정으로 계산한다. 위치·관련 관측·과거 baseline이 필요한 검사는 본 검사를 미실행으로 표시한다. RR/SR/ST의 결측 선검사 9 각 3건은 baseline 검사를 완료한 결과가 아니며, 본 검사 실행 0건·미평가 241건과 구분한다. 이 네 사례가 실제 원천 12종 QC 전수 실행이나 학습 모델의 평가를 대체하지 않는다.

## 직접 확인하는 순서

1. 시험 웹의 품질 현황에서 **샘플 검증**을 선택하거나 `/qc/sample`에 접속한다.
2. 정상·수신 지연·결측·Spike 버튼 또는 목록의 상세 버튼을 선택한다.
3. 시계열 확대, 원문·NULL·수신시각, Rule 입력·threshold, 가상 센서 계약, Evidence SHA를 확인한다.
4. 의견을 입력해 저장·보류·반려·승인을 시험한다. 승인 후에도 후속 단계는 중지한다.
5. 승인된 사례에서 의견과 함께 **샘플 후속 단계 재개**를 선택한다. APPROVE→RESUME→COMPLETE_SAMPLE_DRAFT 이력과 완료 KPI를 확인한다.
6. **샘플 초기화**는 현재 세션의 generation을 올리고 네 사례를 PENDING으로 되돌린다. 다른 세션과 실제 운영 원장은 바뀌지 않는다.

처리 완료 후에도 `approved=false`, `definitive_qc=false`, 운영 쓰기 0건을 유지한다. 의견은 1~2,000자이며 처리 중 중복 조작을 막는다. 이전 revision·추천 SHA 또는 충돌한 request key는 409로 차단하고 현재 상태를 재조회한다. 전역 bootstrap 공유로 같은 key가 다른 브라우저를 연결할 수 있던 초기 설계는 독립 검토에서 수정했다. bootstrap별 멱등성을 사용하며 다른 context의 같은 key는 별도 세션이다.

## 최종 검증

루트의 실제 HTTP 검증 **42개**, DB 접근을 실패시키는 독립 격리 시험 **29개**, backend 집중 시험 **12개**가 통과했다. 집중 41개는 전체 backend 회귀 **1,042 passed / 1 skipped / 18 warnings, 379.49초**에 포함되며 합산하지 않는다. skip은 기존 Windows symlink 권한 미제공 시험이다. 동결한 backend 275개 소스 파일이 전체 시험 전후 동일했다.

프런트 전체 **117/117 passed**, 샘플 집중 **13개** 중 실제 React DOM **9개**가 통과했다. 루트가 동결된 코드로 전체 시험·production build·lint를 독립 재실행해 같은 통과 결과를 확인했다. frontend 98개 소스/시험/의존성 파일이 검사 전후 동일했다. lint 오류 0·기존 경고 12개·샘플 신규 경고 0이며, build의 기존 bundle 크기 경고는 남아 있다. 실제 격리 backend DTO도 9/9 검증을 통과했다.

실제 브라우저 890×836에서 네 사례·값·그래프·지연 marker·결측 공백·확대·의견 저장·보류·반려·승인 시 중지·명시 재개·처리 이력·초기화·운영 화면 복귀 등 **17개 확인**을 통과했다. 수평 넘침과 최종 UI 동결 이후 console 오류는 없었다. 검토 전후 실제 PostgreSQL **12개 표의 행 수와 전체 행 내용 fingerprint가 동일**했다. raw 13,621행과 standard 4,074행을 유지했으며 Rule 결과·source binding·계약·판정·승인·dataset·model·workflow·transition·학습 이력은 각각 0건이다. 샘플 실행은 DB schema 변경도 수행하지 않았다.

고정 네 사례의 첫 context·세션·overview 조회는 0.570초, 같은 세션의 warm overview는 0.021초였다. 작은 샘플의 측정이며 실원천 전수 처리 성능으로 확대하지 않는다. 최종 frontend 결과와 브라우저 증빙 SHA는 [기계 판독 검증 기록](37_QC_SAMPLE_VALIDATION_MODE.json)에 기록한다. 샘플 token·실제 원천·환경변수·원장 행은 공개하지 않는다.

실제 운영 자료 승인·후보 Final QC gate·typed 원천 QC·업무별 학습/평가/serving의 미완료 항목은 [36 운영 경계](36_QC_OPERATIONAL_DASHBOARD_EXECUTION.md)에 남아 있다. 이번 완료 범위는 **직접 조작 가능한 별도 샘플 데이터와 검토 처리**이다.
