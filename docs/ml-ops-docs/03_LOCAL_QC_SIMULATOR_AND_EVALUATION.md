# 로컬 QC 시뮬레이터와 모델 예측 중심 평가 검증

2026-10-20 새로 실행한 7개 비교 중 인천 계절 TEST만 정상 예측 개선·운영 비악화·현재 배포 근거 검사를 함께 통과했다. 후포 계절 TEST의 사후 오탐은 기존 실행 437분에서 162분으로 줄어 Champion 172분보다 적어졌지만, 정상 G 목표의 RMSE와 R²가 악화되어 승격을 보류한다. 이는 각 평가 구간의 판정이며 실제 모델 승격이나 운영 적용을 수행했다는 뜻이 아니다.

올해 주 목표는 모델 예측 정확도 개선이다. 전체 QC 재생은 기존 운영 로직과 함께 쓸 때 FP·FN이 나빠지지 않는지 확인하는 가드레일이다. 설계는 [운영 호환 임계값 전략 계획](03_LOCAL_QC_SIMULATOR_AND_EVALUATION.md), 실행 전후 기록은 `구현 보고서`에 정리했다. 이전 문서는 `변경 전 사본`, 기존 `20261020T012055Z_*` 결과는 과거 기록으로 보존했다.

## Tier 1: 정상 예측 정확도와 잔차 이상 탐지력

이전 네 입력이 실제 G이고 OBS·PRD가 있는 공통 입력창을 먼저 고른다. 그중 현재 목표값도 G인 표본의 MAE·RMSE·R²가 주 평가지표이며, `tier1.models.<model>.normal_prediction`에 표본 수와 함께 저장한다. `normal_g`는 같은 값의 호환 필드다. 세 지표가 악화되지 않고 하나 이상 개선되어야 정상 예측 개선으로 판단한다. 표본이 두 개보다 적거나 목표값이 일정해 R²를 정의할 수 없으면 `r2=null`과 `r2_status`로 이유를 남기며, 임의의 0점이나 1점으로 바꾸지 않는다.

같은 공통 입력창에서 현재 목표값이 G 또는 B인 전체 표본의 최상위 `mae`·`rmse`·`r2`는 별도의 진단값으로 보존한다. 이 값에 B 오차가 포함되므로 정상 예측 주 지표와 섞어 비교하지 않는다. 순수 LSTM 잔차의 `classification`과 `events`도 공통 입력창의 전체 G/B 목표를 사용하며, B가 있으면 잔차 F1과 사건 재현율이 악화되지 않는지 확인한다. 화면의 기존 개별 모델 비교표는 참고 결과로 표시하고 공통 정상창 주 지표와 구분한다.

각 계층의 B 수와 사건 수는 서로 다를 수 있다. 실제 B=0이면 이상치 F1·재현율·사건 탐지율은 `null`, 화면은 `미검증`으로 유지한다. 이때 정상 예측 개선과 Tier 2 비악화를 확인해 승격 기준을 통과할 수 있지만, 그 결과를 이상 탐지력 검증 완료로 표현하지 않는다. 누락된 분모·사건·준비 관측·결측 정보를 임의의 0으로 보충하지 않으며, 실제 기록된 0은 그대로 표시한다.

## Tier 2: 운영 호환성 가드레일

두 모델에 같은 원시 OBS·PRD를 각각 독립된 상태로 순차 공급하고 전체 QC 판정을 비교한다. `online`은 해당 분의 최초 판정, `consolidated`는 이후 Sneaky Drift 등으로 과거 버퍼를 바꾼 뒤의 최종 판정이다. 각 결과에서 후보 FP≤Champion FP와 후보 FN≤Champion FN을 모두 요구한다. FP·FN이 같은 경우도 가드레일을 통과하며, Tier 2 자체의 추가 개선을 승격 조건으로 강제하지 않는다. 모델 예측력의 순위는 Tier 1에서 판단한다.

사후 변경으로 줄거나 늘어난 판정과 실제 최초 알림을 구분한다. `trend_reversal`의 LSTM 단계 경보 취소를 최종 오탐 감소로 세지 않으며, 과거 GAP 플래그가 Drift로 바뀌어도 원시 관측이 복구된 것으로 해석하지 않는다. 이상 탐지 사건 수·재현율과 준비 관측이 없는 외부 구간의 한계도 함께 남긴다.

## 원본 운영 코드가 읽는 DEV와 세 임계값

후보 번들의 모델·scaler와 함께 전달하는 `Thres.forecast.DEV`에는 단일 float인 `operational_deploy_threshold_3sigma_cm`를 기록한다. 수정하지 않은 운영 코드는 이 값을 두 곳에 사용한다. LSTM에는 기존 계단식 `f(DEV)=(DEV/3)*effective_sigma`를 적용하고, 편향 검사에는 같은 DEV에 관측소 배수를 곱한다. 화면과 메타데이터는 다음 값을 나란히 보여 준다.

| 값 | 의미 |
|---|---|
| `raw_threshold_3sigma_cm` | VALIDATION 정상 오차에서 계산한 순수 통계 3σ다. 배포값으로 덮어쓰지 않는다. |
| `operational_deploy_threshold_3sigma_cm` | 실제 DEV 파일에 기록하고 편향 검사에도 전달하는 운영 배포 호환 3σ다. |
| `effective_lstm_threshold_cm` / `effective_threshold_cm` | 원본 계단식으로 실제 DEV를 변환한 유효 LSTM 임계값이다. |

DEV는 후보 통계 raw와 Champion raw 이상이어야 하고, `f(DEV)`는 후보 보정 목표와 Champion 유효 임계값 이상이어야 한다. 계단 경계에서 함수값이 내려가므로 단순 `max(raw, champion_raw)`만 사용하지 않고 구간별 역산으로 두 하한을 만족하는 가장 작은 float를 찾는다. 기존 보정 목표는 `calibrated_effective_threshold_cm`에 따로 보존한다. 새 학습에서는 배포 인코딩 뒤 같은 VALIDATION 정상·B 오차로 FP·FN과 보정 검사 결과를 다시 계산하며 TEST를 임계값 선택에 사용하지 않는다.

작성기는 float를 왕복 보존하는 문자열로 DEV를 저장하고 sidecar에 DEV 해시를 기록한다. 로더는 artifact·sidecar·자산 해시와 통계 raw·실제 DEV·계단식 유효값을 확인하며, Champion 기준도 동결 manifest의 실제 값과 대조한다. 재생기의 편향 검사는 운영 DEV를 소비하고 LSTM은 그 DEV의 계단식 유효값을 한 번 적용한다. 저장 후 재개하는 상태의 식별값에도 운영 DEV를 포함한다. 이전 직접 유효 임계값 정책은 과거 기록으로 읽을 수 있지만 현재 배포와 같다고 표시하지 않는다.

새 학습기의 `finalize_operational_calibration()`은 배포 임계값을 확정한 뒤 VALIDATION의 FP·FN·F1과 보정 검사 결과를 다시 계산한다. 이번 기존 번들 이전에서는 인천 계절·후포 계절·묵호 계절의 유효 LSTM 임계값이 저장된 보정 목표와 정확히 같아 기존 VALIDATION 기록을 보존했다. 이를 새 VALIDATION 추론을 수행한 것으로 표현하지 않는다.

후포 기존 분할 후보는 유효값이 `5.802191885020495 → 7.751364557187159 cm`로 바뀌었다. 기존 VALIDATION 예측 배열이 없어 새 임계값의 결과를 재계산할 수 없으므로 `calibration_guardrails_available=false`, `calibration_guardrails_passed=null`, `validation_tp_count/fp_count/fn_count`와 F1 등을 `null`로 기록했다. 이전 점수는 `calibrated_*`에 보존한다. 이 미검증 상태를 보정 검사 통과로 바꾸거나 TEST로 보충하지 않았다. `번들 변경 기록`에서 변경 파일과 모델·scaler 보존을 확인할 수 있다.

후보나 평가 스냅샷·범위를 바꾸면 이전 차트와 QC 표를 먼저 비운다. 각 요청은 실제 조회 대상과 요청 세대를 보관하고 응답·오류를 반영하기 전에 다시 확인한다. 고정된 시뮬레이션 조회는 후보·시뮬레이션 ID를, 후보 시계열 조회는 해당 후보의 실제 평가 snapshot·scope·비교 해시를 확인한다. 앞으로 실행할 평가 스냅샷 드롭다운이 자동으로 갱신됐다는 이유만으로 이미 선택한 기록의 응답을 버려 로딩 상태가 남지 않게 한다. 선택 해제 뒤 늦게 온 응답, 이전 후보 평가 완료, 이전 시뮬레이션 작업 완료가 새 화면을 덮어쓰지 않는다. 화면 확인만으로 모델 등록·alias 변경·실제 운영 배포가 수행되는 것은 아니다.

# 운영 호환 임계값과 모델 예측 중심 평가 구현 계획

사용자가 지정한 UTF-8 전략 문서의 세 전략을 구현한다. 올해 목표는 모델의 정상 예측 정확도 개선이며, 전체 QC 재생은 기존 서브알고리즘과 함께 쓸 때의 비악화를 확인한다. 원본 백업은 읽기 전용으로 유지하며, 구현 당시에는 commit·push·운영 DB 갱신·실제 승격을 수행하지 않았다. 이후 사용자의 별도 요청으로 진행하는 소스·시험·문서 전송은 [42_AI_QC_MLOPS_ENGINE_INTEGRATION.md](../42_AI_QC_MLOPS_ENGINE_INTEGRATION.md)에 기록한다.

## 확정한 설계

순수 통계 raw 3σ와 실제 DEV 값을 분리한다. 배포 DEV의 하한은 후보 raw와 챔피언 raw의 최댓값이며, 원본 계단식을 거친 유효 LSTM 값의 하한은 후보 보정 목표와 챔피언 유효값의 최댓값이다. 다섯 계단 경계에서 함숫값이 낮아질 수 있으므로 구간별 역산과 float 재해석으로 두 조건을 함께 만족하는 가장 작은 배포값을 구한다. 원본 코드의 수식을 바꾸거나 시뮬레이터에만 별도 임계값을 주입하지 않는다.

Tier 1의 주 지표는 이전 네 입력이 실제 G인 공통 창 중 목표도 G인 표본의 MAE·RMSE·R²다. 각 값이 악화되지 않으며 하나 이상 개선되어야 한다. 동일 입력창의 전체 G/B 목표에서 순수 LSTM 잔차 F1과 사건 탐지율도 비악화를 확인한다. B=0이면 이상 탐지 미검증을 유지하면서 정상 예측 개선과 Tier 2 비악화를 판정한다. R²가 정의되지 않는 작은 표본·일정한 목표값을 임의의 점수로 바꾸지 않는다.

Tier 2는 online과 consolidated 각각 FP≤챔피언 FP, FN≤챔피언 FN을 요구한다. 추가 개선을 강제하지 않는다. 실제 배포 DEV와 시뮬레이터 소비값·해시·정책의 일치도 검사한다. 이전 정책의 결과는 조회할 수 있지만 현재 승격 근거가 되지 않는다. 인천·후포가 반드시 통과하도록 기준을 바꾸지 않고 실제 재실행 결과를 기록한다.

교차 검토에서 확인한 세부 동작도 같은 승인 범위에서 맞춘다. Tier 2 하위 판정과 문구도 FP·FN 비악화를 뜻하도록 통일하며, 조회 API는 저장 당시 판정을 별도 이력으로 남기고 현재 판정을 일관되게 반환한다. 실제 승격 근거는 snapshot·scope 이름뿐 아니라 전체 평가 시작·종료 시각도 같아야 한다. 짧게 잘라 재생한 결과를 전체 TEST 검증으로 대신하지 않는다. UI는 현재 근거를 요구하고 이전 후보의 늦은 응답을 버리되, 해당 요청과 무관한 준비용 선택값 변경으로 올바른 응답까지 버려 로딩 상태에 남지 않도록 시험한다.

## 작업과 검증 순서

1. 기존 변경 상태·전략 문서·원본 해시·후보 4개의 변경 전 사본을 보존한다. `00_OVERVIEW_AND_INDEX.md`에 승인된 설계를 먼저 반영한다.
2. `calibration_policy.py`에 계단식 소비와 운영 배포값 인코딩을 구현한다. 다섯 경계와 바로 다음 float, 배포값 재읽기, 두 하한을 시험한다. 학습기는 DEV에 배포값을 기록하고 통계 raw·보정 목표·실제 유효값과 별도 검증 보정 결과를 구분한다.
3. 후보 로더·재생기·평가기·CLI에 배포 동등성과 R²·정상 목표 주 지표를 연결한다. 기존 직접 임계값 번들을 거부하지는 않되 현재 운영 호환 승격 자격과 구분한다. 원본과 같은 DEV에서 같은 LSTM·Drift 기준을 얻는지 시험한다.
4. `evaluation_safety.py`의 공통 판정을 후보 조회·실제 승격 전 검사·API에 연결한다. UI에서 주 지표·운영 호환성·통계 raw·운영 DEV·유효 LSTM을 구분하고 없는 값은 미검증으로 표시한다. 현재 번들과 결과가 맞지 않으면 승격을 막는다.
5. 변경 전 사본과 SHA를 남긴 뒤 지정된 후보 4개의 DEV·임계값 sidecar·artifact와 관련 해시만 갱신한다. 모델·scaler는 그대로 둔다. 이전 7개 실행을 수정하지 않고 새 7개를 실행한다.
6. 저장 CSV·시계열에서 지표를 독립 재계산하고 공통 입력·원본 해시를 대조한다. API의 목록·상세·series와 화면에서 같은 최신 결과가 보이는지 확인한다. 두 Python 환경의 신규 시험과 전체 회귀시험을 실행한다.
7. `00_OVERVIEW_AND_INDEX.md`, 상세 문서 07, 구현 보고서와 새 집계를 실제 수치로 동기화한다. 미통과 후보·B=0·준비 관측이 없는 구간·제어 환경 TensorFlow 제약을 구분한다.

## 파일 소유권과 진행 기록

`strategy_calibration`은 보정 정책·학습기·관련 시험, `strategy_backend`는 승격 기준·lifecycle·dashboard API·관련 시험, `strategy_ui`는 화면·UI 시험을 맡는다. 루트는 로컬 재생·평가·번들 이전·실제 실행·문서·통합 검증을 맡는다. 같은 로컬 번들과 실행 환경을 함께 검증해야 하므로 사용자가 지정한 현재 checkout에서 파일별 소유권을 지켜 진행한다. 실행 상태는 `reports/local_qc_simulations/development/strategy_20261020T0421/progress.md`에 남긴다.
